# 通用流程文档

本文档描述 `anglan_crawler` 当前代码的通用处理链路。站点 XPath、JSON 路径、图片规则和等待条件属于站点适配层，分别写在具体 Spider 或采集脚本中。

## 1. 总体流程

```text
Excel（分类 + 商品 URL）
        │
        ├─ 02crawler：从分类页收集详情页 URL
        │
        ├─ shopify_json：访问商品 .json 接口
        │
        └─ not_shopify：用 Selenium 渲染商品页
                │
                ▼
统一商品表（10 列）
        │
        ▼
03switch：Shopify / WooCommerce / 价格 / SKU 转换
```

## 2. 统一数据契约

所有详情采集器最终使用以下字段：

| 字段 | 含义 |
|---|---|
| `title` | 输入表第一列的分类名 |
| `name` | 商品名称 |
| `price1` | 当前销售价 |
| `price2` | 原价；没有原价时通常回退为当前价或为空 |
| `styles1` | 第一组选项和变体价格 |
| `styles2` | 第二组选项 |
| `styles3` | 第三组选项 |
| `src_links` | 图片 URL，多个 URL 用 `#` 分隔 |
| `link-href` | 商品原始 URL |
| `details` | 商品描述 |

`styles` 的基本格式为：

```text
OptionName#OptionValue$price1$price2@image#OptionValue2$price1$price2@image
```

多组选项使用 `&` 追加选项名和选项值，例如：

```text
Color#Red&Size&M$19.99$29.99@https://example.com/red-m.jpg
```

## 3. 输入约定

详情 Spider 读取 `.xlsx` 的活动工作表：

- 第 1 行是表头。
- 第 1 列是分类名。
- 第 2 列是商品详情页 URL。
- 从第 2 行开始读取。
- 空 URL 会被跳过；`shopify_json` 按 `.json` URL 去重。

链接采集脚本的输出只有两列：

```text
title, link
```

## 4. 阶段一：详情页链接采集

`02crawler` 下有三种通用模式：

| 脚本 | 适用页面 | 主要机制 |
|---|---|---|
| `detail_link_page.py` | 分页列表 | 拼接 `?page=N`，无新链接时停止 |
| `detail_link_scroll.py` | 无限滚动 | 滚动并比较 `scrollHeight`，连续无变化时停止 |
| `detail_link_click.py` | “加载更多”按钮 | 定位按钮、点击、比较链接数量，按钮消失或连续无新增时停止 |

三个脚本都使用浏览器和 XPath 提取链接，自动将相对链接转成绝对 URL，并对分类内和全局结果去重，输出到 `02crawler/output`。

`02crawler/Crawl` 保存按站点定制的链接采集脚本；`02crawler/Json_Crawl` 保存直接访问 Shopify JSON 的独立脚本，不应与 Scrapy Spider 混淆。

## 5. 阶段二：商品详情采集

### 5.1 Shopify JSON

目录：`shopify_json/`

适用于能够访问商品 JSON 接口的 Shopify 商品页。Spider 将 URL 转换为同路径 `.json` 地址，读取 `product` 对象，再通过 `utils/json_variants.py` 统一处理：

- 变体和选项组合
- 当前价和比较价
- 货币换算为 USD
- 图片 URL 和变体图片
- 商品 HTML 清洗

公共 Pipeline 会：

1. 收集统一字段。
2. 合并 `src_links` 与 styles 中的 `@image`，最多保留前 5 张普通图片并去重。
3. 输出 `*_styles.xlsx`。
4. 调用 Shopify 转换器生成 Shopify 表和价格匹配表。

当前 Spider 在 `shopify_json/shopify_json/spiders`，归档 Spider 在 `Historical`。归档目录中的文件仍是可参考的站点适配代码，但不代表当前业务入口。

### 5.2 非 Shopify / 需要渲染的站点

目录：`not_shopify/`

当前仓库实际启用的 Spider 为 `quince`。请求中通过 `meta` 传递等待 XPath 和额外等待时间，`SeleniumDownloaderMiddleware` 负责：

1. 打开 URL。
2. 等待关键 XPath 或 `body` 出现。
3. 额外等待页面 JS 完成。
4. 读取 `document.documentElement.outerHTML`。
5. 封装成 Scrapy `HtmlResponse`。

`ValidateSpiderMiddleware` 会检查核心字段是否全部为空。连续达到 `EMPTY_THRESHOLD`（当前为 3）后重启浏览器并重新请求失败页面。

### 5.3 选择路线

```text
标准 Shopify 商品 .json 可访问       -> shopify_json
需要 JS 渲染或自定义 DOM 提取         -> not_shopify
只需要收集分类页详情链接              -> 02crawler
需要单文件快速采集 Shopify JSON       -> 02crawler/Json_Crawl/run2.py
```

## 6. 阶段三：格式转换

标准转换链路：

```text
*_styles.xlsx
    -> Shopify 原价表
    -> Shopify 选项拆分表
    -> 价格匹配表 / 未匹配价格表
    -> WooCommerce WP CSV
```

`03switch` 脚本职责：

| 文件 | 作用 |
|---|---|
| `01转shopify.py` | styles 转 Shopify，旧版单文件脚本 |
| `01转shopify_价格排序.py` | styles 转 Shopify 并执行价格匹配，旧版单文件脚本 |
| `02价格排序.py` | 对 Shopify 文件执行价格匹配 |
| `03shopify转WP.py` | Shopify CSV 转 WooCommerce CSV |
| `04价格检查.py` | 检查 WP CSV 中的价格是否命中价格库 |
| `05wp还原为styles.py` | WP CSV 还原为统一 styles Excel |
| `06SKU更新.py` | 重生成父级和变体 SKU，并修正 Parent 引用 |
| `06SKU独立查重.py` | 检查重复 SKU 和孤立变体 |

`03switch/exe/switch_gui.py` 将这些功能和 Spider 生成器包装成 GUI。

## 7. 输出目录

当前代码的主要输出位置：

```text
shopify_json/shopify_json/output/<输入分组>/<时间戳>/
not_shopify/output/<时间戳>/
02crawler/output/
```

实际业务产出还会写入输入文件附近的 `xlsx`、`csv` 子目录，或写入 `A产出` 中的业务目录。脚本顶部硬编码的 `INPUT_FILE` 可能指向历史路径，运行前必须检查。

## 8. 新站点接入

1. 准备分类名 + 商品 URL 的 Excel。
2. 判断站点使用 Shopify JSON 还是需要浏览器渲染。
3. 复制最接近的现有 Spider 或使用 GUI 的“生成 Spider”。
4. 修改 `name`、`allowed_domains`、`INPUT_FILE`。
5. 配置站点 XPath、等待条件和必要的图片/JSON 特殊逻辑。
6. 先用 1~10 条数据验证 10 个统一字段。
7. 检查 `styles` 分隔符、图片数量、价格和详情 HTML。
8. 再执行全量运行，并检查 Shopify/WP 输出。

## 9. 运行前检查

- Chrome 是否已安装。
- `requirements.txt` 及按需依赖是否安装。
- 是否需要 `127.0.0.1:7897` 代理。
- 输入 Excel 的列顺序是否正确。
- Spider 的 `TEST_MODE` 是否关闭。
- 输出目录是否有足够空间。
- 目标站点是否允许访问和采集。
